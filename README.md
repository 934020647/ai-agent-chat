# AI Agent Chat Platform

This project is a cloud-deployed AI chat platform for the challenge project.

Planned features:

- Public web page deployment
- LLM-based text chat
- Streaming response
- Intent recognition
- Task decomposition
- ReAct-style agent reasoning
- Multi-agent collaboration
- RAG retrieval
- Multimodal extension
- GitHub-based code submission

## Deployment Target

- Cloud Server: Alibaba Cloud ECS
- OS: Ubuntu 22.04
- Frontend: React + Vite
- Backend: FastAPI
- Web Server: Nginx

## Stage 2: Kimi API Integration

### Configure Kimi API

Create `backend/.env` and add your real Kimi API key:

```bash
cd /root/ai-agent-chat/backend
cp .env.example .env
nano .env
```

Example content for `backend/.env`:

```env
OPENAI_API_KEY=your_real_kimi_api_key_here
OPENAI_BASE_URL=https://api.moonshot.cn/v1
MODEL_NAME=kimi-k2.6
```

> **Do not commit `backend/.env`.** It is already ignored by `.gitignore`.

### Behavior

- If `OPENAI_API_KEY` is set → backend calls **Kimi API** (`mode: "llm"`)
- If `OPENAI_API_KEY` is missing → backend returns **mock response** (`mode: "mock"`)
- If Kimi API call fails → backend returns **friendly fallback** (`mode: "error_fallback"`)

### Reinstall Backend Dependencies

```bash
cd /root/ai-agent-chat/backend
source .venv/bin/activate
pip install -r requirements.txt
```

### Test Backend (Mock Mode)

Remove or comment out `OPENAI_API_KEY` in `backend/.env`, then:

```bash
curl -X POST http://127.0.0.1:8000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"hello"}'
```

Expected: `mode` is `"mock"`.

### Test Backend (Kimi API Mode)

Add a valid `OPENAI_API_KEY` to `backend/.env`, restart the backend, then:

```bash
curl -X POST http://127.0.0.1:8000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"请用三句话介绍一下人工智能 Agent"}'
```

Expected: `mode` is `"llm"` and `reply` is generated by Kimi.

## Stage 3: Intent Recognition and Task Decomposition

### Architecture

`/api/chat` now delegates to `agent/orchestrator.py`:

```text
/api/chat
  └── orchestrator.handle_chat(message)
        ├── intent_agent.classify(message)   → intent
        ├── planner_agent.plan(intent)       → tasks
        ├── llm_client.generate_reply(...)   → reply (if API key exists)
        └── build steps + mode               → steps, mode
```

### Supported Intents

- `general_chat`
- `technical_question`
- `coding_task`
- `deployment_help`
- `research_summary`

## Stage 3.7: Kimi Token Streaming

### What's New

`/api/chat/stream` now supports token-level streaming from Kimi API:

- **delta events**: Push partial reply tokens as they are generated
- **final event**: Confirms the complete response
- **Frontend**: Real-time incremental rendering of the Final Reply

### Test Streaming

```bash
curl -s -N -X POST http://127.0.0.1:8000/api/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"message":"请用 Markdown 格式列出部署 React + FastAPI 的三个步骤"}'
```

Expected event sequence:
1. `status` — Received the user message
2. `status` — Recognizing user intent
3. `intent` — Intent recognized
4. `status` — Decomposing the task
5. `tasks` — Task list generated
6. `status` — Calling Kimi API
7. Multiple `delta` events — Reply tokens stream in
8. `final` — Complete response
9. `done` — Stream complete

### Fallback

If the streaming endpoint fails, the frontend automatically falls back to the non-streaming `POST /api/chat`.

## Stage 4: ReAct-style Workflow

### What's New

Added a lightweight ReAct-style action trace to show safe, user-visible execution steps.

**New module:** `agent/react_agent.py`

- Generates action/observation pairs based on intent
- Does **not** expose hidden chain-of-thought
- Does **not** call external tools
- Only produces demo-friendly execution summaries

**Example `react_trace`:**

```json
[
  {
    "action": "classify_intent",
    "observation": "Recognized user intent as deployment_help"
  },
  {
    "action": "decompose_task",
    "observation": "Generated deployment steps for cloud environment"
  },
  {
    "action": "prepare_model_prompt",
    "observation": "Prepared context with deployment checklist"
  },
  {
    "action": "stream_response",
    "observation": "Streaming deployment guide to frontend"
  }
]
```

### API Changes

Both `POST /api/chat` and `POST /api/chat/stream` now return:

```json
{
  "reply": "...",
  "intent": "...",
  "tasks": [...],
  "steps": [...],
  "retrieved_context": [],
  "mode": "llm",
  "react_trace": [
    {"action": "...", "observation": "..."}
  ]
}
```

Streaming adds a new event type:

```json
{"type": "react_trace", "react_trace": [...], "mode": "thinking"}
```

### Frontend Changes

A new **ReAct Trace** panel displays action/observation cards below Mode.
